# 当前执行主线：高精度整图基线与区域缓存

更新：2026-10-19，依据用户明确指令。本文优先于旧实验日志中的下一步排程；旧结果保留为证据。

## 目标与研究顺序
主线是变化区域重算、不变区域复用对齐后的历史特征。当前阶段先建立精度接近原INT且适合区域跳算的整图基线，再在同一可靠基线上比较缓存策略。残差/门控缓存是备选机制，不替代主线，不自动优先占用空闲GPU。

原INT完整BEV AP70=75.87361%，暂沿用差不超过0.5个百分点（约75.37%）的工程目标。该门槛是阶段目标，不表示统计显著性或已证明新架构可达到。低精度模型的速度不能作为路线成功依据。

## 整图基线必须同时满足的结构条件
- 整图版本对应“所有区域都选择更新”；后续区域版复用同一套主要权重与算子，不另外造一套语义不一致的低精度网络。
- 缓存保存明确网格上的特征/状态、坐标、覆盖和年龄；未选位置保留对齐缓存，选中位置才计算并写回。新视野、过期和场景切换有明确刷新规则。
- 主要昂贵空间计算应位于可选执行路径内。选区可以依靠便宜的当前观测，但不能先完整执行昂贵编码器/上下文再决定是否省算。现有v2/v2n只具备更新模块局部性，完整空间编码仍每帧计算，因此只是精度/状态学习对照，尚未满足整个高效路线的要求。
- 每个可缓存算子的空间依赖、步长、halo和全局边界可计算。使用逐点通道归一化或固定统计；跨全图统计、全局注意力和全图上下文不能隐藏为免费依赖。若需上下文，应明确它是否缓存、按低频刷新及相应代价。
- 不强制单尺度单状态，也不强制0.21M/2.47M参数上限。允许多尺度缓存和较强的局部卷积，只要多尺度依赖能局部展开，读出足够轻或也具备缓存边界。借用预训练空间模块时，不能因为保留了整套INT就宣称满足高效目标。
- 全更新与参考模型、局部更新与相同选区的整图计算后局部写回分别验收；计时包括选区、对齐、halo、索引/搬运和检测读出。不将选中面积比例直接当作MAC或整网加速比例。

## 架构修订的条件与方向
若第20轮及拟合诊断仍显示明显精度瓶颈，优先构建从成熟空间表征出发的可局部执行整图模型，而非继续把所有层压薄或仅增加不能跳过的全图上下文。候选方向：廉价当前描述→区域选择接口→可缓存的多尺度局部空间编码/状态更新→轻量读出。整图训练阶段选择接口全选，先训练精度；成熟模块权重尽量迁移，必要时用适配层/蒸馏做表示过渡。

这只是下一设计约束，不是已实现/已启动的第三版。正式实施前需列出缓存位置、可跳过的层、必要halo、不可跳过成本和初始化映射，避免再将容量、初始化与全部结构同时无记录改变。缓存策略比较在可靠整图基线上进行；优先比较直接复用最终特征，残差/门控复用作为附加对照。更换主策略需要同权重、同序列、同GPU配对精度/延迟/内存证据。
