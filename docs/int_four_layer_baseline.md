# 四层局部复用：已验证阶段基线与后续优化计划

记录日期：2026-10-25（北京时间）。依据用户本轮确认，本文是本研究路线当前阶段结论；后续实验不得用尚未完成的两层结构覆盖此基线。

## 1. 明确阶段结论

**“完整历史H对齐、变化区域真实重算、未选位置直接复用”的核心方案已经完成实现及完整验证。** 它在接近成熟参照精度的条件下减少了实际执行面积和卷积/线性算量。当前任务是优化精度—算量—延迟权衡，并扩大可复用计算范围，不再把“重新设计足够多的网络模块”或“两层网络成功”作为阶段完成条件。

整体仍属于INT成熟骨架；局部改造包括第一级内部四层U的输入投影压缩、最终H缓存及真实选区执行。保留成熟骨架不妨碍阶段目标成立。已验证的是实际少算，尚未取得相对成熟缓存参照的GPU净延迟收益；没有证明SNN独立价值、多种子统计优势或能耗下降。

## 2. 固定结构和状态语义

当前点云 → Pillar → 低秩GRU（自己的对齐hidden）→ 第一级首个成熟残差块 → 当前E → 四层空间更新U → 第一级输出H → 既有深层刷新/修正、读出与检测。

- E与H均为128×100×252；H是第一级输出，不是第三级特征。
- U保留两个残差块的四层空间卷积、BN及激活；各层由1×1的128→96投影和3×3的96→128卷积组成。BN使用固定统计量。
- 普通帧先按自车位姿以SE(2)最近邻对齐完整历史H及比较参考。当前E的16通道分组均值描述子，与对齐且随H保留的历史参考作4×4块归一化RMS比较。
- 最终重算核心M为内容变化区域、未覆盖区域、上一帧自身置信度≥0.1的检测区域外扩4格的并集。内容核心本身不额外扩张。无GT/教师/当前昂贵检测结果参与选择。
- 四层依赖支持为M外扩3/2/1/0格；投影支持为4/3/2/1格。选中H基于完整当前E依赖重算，其余位置直接沿用对齐历史H。
- 只持久保存最终空间H；中间激活是当前帧临时活跃行，不消费旧中间激活。H比较参考只在最终选中格更新，避免每帧更新参考掩盖慢变化。
- 空间完整刷新period3、最大完整年龄0.25秒，另有场景/FM重置保护。既有深层D缓存也保持period3。两类状态各自对齐，GRU/H/D不可混称一份状态；没有目标运动预测。
- 深层D路径是紧凑读出中的深层投影贡献：刷新帧运行第二、三级及相应上采样/投影，普通帧用当前H与对齐D做小模块修正。它与早期分别修正第二、三级的两个小模块不是同一实现。

## 5. 下一阶段计划与判定顺序

### 第一优先：定位剩余计算，而非继续无差别缩短U

当前成熟缓存总134.31G中，U原为29.73G；四层保守局部版U约14.85G，其余约104.58G保持。先在固定基线做分模块实际MAC和刷新/普通帧分开计时，统计整段按真实刷新频率加权的成本。利用已有512帧profile作为起点，避免重复无目的诊断；CUDA嵌套span不得相加，GPU延迟与算量分开排序。

候选包括：每帧空间读出卷积/当前上采样支路，以及完整刷新时第二、三级主干。先测量各自占比、必要依赖范围和缓存字节，再选一项扩大局部复用；不能预设最深模块一定是当前最大成本，也不能忽略它已经在多数帧被深层修正替代。高分辨率GRU门三套缓存此前收益差，不重复作为默认方向。

### 并行优化：固定四层基线，分别改善选区与执行

- 精度/算量：基于训练集分析被复用区域误差是否来自目标移动、新出现区域或缓慢变化，评价当前描述子和置信保护的漏选/冗余。必要时训练小选择器预测缓存误差或检测敏感区域；教师完整特征只生成训练监督，部署选择必须在昂贵计算前完成。先做相近执行面积的对照，不把多算区域误判为选择器更好，也不再无界扫阈值。
- 延迟：已有统一索引和权重预排保留。针对剩余邻域gather/小算子开销，比较较规则的区域批处理与现有活跃行执行；必须照计多计算的边缘面积和临时内存。优先保持相同输出语义；改变选区形状时另设同掩码密集对照，区分策略误差和执行误差。
- 两层Plain/Context是可选更新模块优化，不再作为主线前置门槛。当前BN配对收尾后，不自动延训或替换固定四层基线。

### 扩展实验：保留当前证据，缓存更大模块的完整输出

优先对实测占比较大的空间读出模块研究“缓存读出后完整特征、只局部重算”，检测头先保留每帧完整执行；若读出收益上限小或误差难控，再研究深层模块按区域刷新。两者均先核验全更新模式重现固定模型，再评估缓存。

不能直接把第一级M复制到下游：深层修正D即使在H复用位置也可能变化，读出卷积/上采样亦有邻域依赖。新选择应检查该模块实际输入与匹配历史参考，或建立覆盖全部变化来源的保守依赖传播。新状态整图位姿对齐，未选输出直接保留，选中输出以当前输入及完整依赖重算；缓存完整输出，不能改成每帧全图更新状态却只缓存门控/残差。显式计入新增对齐、参考、周期刷新及内存成本。

### 验证与采用规则

每项候选比较固定四层主基线、同结构全更新、同掩码密集算后写回、真实局部执行；分别测AP50/AP70、最终写入与实际执行面积、加权GFLOPs、均值/P95、状态和临时内存。先训练片段工程核验，再完整5794扫描闭环验证，禁止用教师状态修补学生历史。结构变动单独先通过整图精度核验。

同精度更低计算量或延迟优先；有明确精度代价则作为权衡点保留，不覆盖原基线。不把GPU延迟作为唯一成功条件，也不以少FLOPs直接宣称能耗下降。使用181空闲GPU并行独立候选，不影响其他账号；一小时路线级定时检查保持，完成或异常通知。
