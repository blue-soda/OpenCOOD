## 目的和协议

E0两帧表明同一512事件发8/2/1包可得到逐值相同预测，但元数据重复很昂贵。本项固定原联合best、IF映射、所有事件及其顺序、读出位置；仅比较运输格式，不能把节省bytes写成已提高AP。

使用验证集最前64帧、无增强、seed20260929；原联合best SHA f4a5795b8b001a7cc4c04fd9eb3959f02df70181afe23691e733cb3aa4eb8588，E0配置，全部源特征，IF上限8。在每帧缓存同一次编码产生的完整有序地址事件及完整元数据，后续格式共享该序列，不独立重算特征。

固定前缀512/2048事件（不足则实际全部），每包容量64/256/1024，三种格式：

1. raw_v1：原始每事件uint32地址，每包完整JSON身份/几何元数据。
2. session_raw：首包完整元数据，后续包携带该会话SHA256、起始序号、数量和CRC；地址原始uint32。
3. session_zlib：与session_raw相同，仅对每包有序地址字节做无损zlib。

首包会话元数据实际收费，不假设免费缓存；新帧、位姿、编码器、basis和阈值设置改变时必须新会话。所有格式保留同址重复、顺序与单位事件，不做排序或计数合并。接收端拒绝首包缺失、重复/不连续序号、错误会话/网格、CRC损坏和超过注册上限的计数。所有非空首包至少携带完整元数据；零事件0包/0bytes。

每帧每种格式核验有序事件完全相同、源网格整数计数完全相同；容量256时raw_v1与session_zlib在两个固定前缀上还要比较真实检测预测逐值一致。输出逐帧实际bytes、均值/P95、封装/验证解码参考耗时。耗时包含Python重复校验，不当优化生产实现或独占性能证明。

另外在容量256下对raw_v1/session_zlib执行2048/4096/8192bytes硬预算准入，报告实际事件数与字节。压缩长度不保证单调，compact准入对最后一块从最大长度向下逐一试验，不用不成立的二分查找。它是固定块划分下的贪心可行前缀，不保证所有可能分包中的全局最优；相同总字节下两格式可能含不同事件，因此不做预测等价主张，也不报告AP。
