## 下一步：固定内容，区分通信税与消息粒度

假设而非结论：逐通道单位事件反复携带空间地址，可能支付过高地址成本；按单通道强度排序也可能先发送零散证据，完整空间位置的通道组合是否更有利于高IoU检测尚待检验。这两件事需要分开验证。

冻结当前receiver best：`/data1/tzm/workspace/diagnostics/e3dsnn_event_receiver_20261021/receiver/train/best_ap70.pth`，SHA256=`60b7e0ff84e992862902aa9325b56ac13ab5658d70c4aacb194028638f5105dc`。不改变P、D、已有门控/尺度、编码器、ANN BEV、连续头、Count4读出、上限8、坐标对齐或后处理。

1. **先做64帧同内容成本对照，不训练。** 固定验证前64帧、共享每帧同一次源编码，在原4096/8192/16384bytes停止点取累计整数计数。记录总事件、唯一通道地址、唯一体素、各体素有效通道数和计数分布。只比较现有单位事件格式与一种“空间坐标＋通道掩码＋非零整数计数”的合并表示，序列化元数据和头部全部计费。不扫描压缩算法、通道宽度或发放上限。
2. **先验证语义。** 对同一截止点，合并表示解码的CZYX计数、对齐后接收状态、检测输出必须逐值一致；保留源frame/姿态/网格/通道basis约束，拒绝错坐标和错版本。该成本对照是累计计数快照，不是已经实现的在线增量协议；不能把快照反复相加。若将来改成增量，必须携带序号和仅新增计数，专门验证重放/丢包/重复状态。
3. **再决定是否做空间组选择对照。** 仅当同内容成本对照通过且有实际节省时，才准备全量4/8/16KiB的同预算推理对照。候选为一个源体素内多个脉冲通道共用空间地址，仍发送整数计数；保持同一个完整计数张量，比较单位事件前缀与完整体素行选择。体素排序只能用发送端信息，初始固定为首个IF越界时刻排序，明确此时发送完整行属于帧内离线优先级调度，不能宣称严格在线神经元时间因果。该阶段无新增评分器、无新训练。
4. **归因与退出。** 同内容解码相同而字节减少只能归因于表示/协议；同预算改变行选择的AP变化也不单独证明SNN优势。若合并成本不划算或行选择仍无合格AP，停止该有界对照，回到旧低通信候选的任务表征设计。只有得到可行曲线后才登记新的可学习、空间一致的脉冲簇方案及强ANN同协议对照，不能把本页候选直接包装成创新完成。

步骤1–2已实现为独立诊断脚本`profile_e3dsnn_event_granularity.py`：空间行使用uint32地址、32位通道掩码及非零4bit计数（保留0–8范围），完整元数据与CRC均计费，zlib与现有格式一致。增加同一有序事件前缀合为单包的控制，以分离分包开销；合并计数快照还丢失前缀内部顺序，必须明确与单包有序流的语义差别。2项CPU检查通过（空/稀疏计数、错身份/损坏/越界拒绝）；真实64帧检查尚待执行。没有新AP或训练任务。
