## 总目标与用户约束

用户指出当前方案二参数明显少于强ANN，允许适当扩大模型，要求AP70不要落后两强ANN太多。以通信预算下的精度为优先，不把最小参数量当作目标。方案二和现有IF脉冲发送机制保留，方案三继续暂停。参数量本身不证明延迟/能耗优势，也不能弥补任意大的AP差距。

现有3.120631M总参数中，SNN三维主干1.722368M、ANN BEV后端1.293056M、连续检测头0.005140M；其余为消息映射/接收器及继承的融合模块。InfoCom的大部分参数在通信模块，不能仅凭119.85M对3.12M就断定我们的检测主干容量不足。

## 可证伪假设和首轮主对照

假设：在固定方案二脉冲表征与实际2KiB预算下，现有BEV后端容量限制了检测性能；增加接收后端容量能更充分利用本车和协作信息。此假设不同于“更大的发送端生成更有用的脉冲”，首轮不混淆两者。

| 项目 | C0小后端对照 | C1大后端候选 |
|---|---|---|
| BEV两级通道 | 64/128 | 128/256 |
| 两路上采样输出 | 128/128 | 256/256 |
| 检测头输入 | 256 | 512 |
| 总参数预核算 | 3,120,631 | 6,556,919 |
| 3D输出/脉冲消息 | 相同128通道3D表征→32通道IF消息 | 相同 |
| 字节上限/空间坐标/时间语义 | 保持现有真实2KiB硬预算和对齐契约 | 相同 |

预核算来自181 CPU上的真实模块实例，宽度1复算恰好等于原3,120,631；宽度2仅统计拟替换的BEV及头，尚非已完成的扩容检测器。激活仍为当前ANN BEV的ReLU，SNN编码与IF发送不变。参数增加3,436,288，不能将新增ANN后端容量自身称为SNN创新。

两臂从同一已复核fixed2k第6轮best出发，首轮冻结3D编码器、消息投影/解码、接收器，只训练各自BEV及连续检测头。对同一输入，网络传输内容保持相同；用小模型在相同冻结范围下再训练作对照，不能直接把旧58.85365%与多训练一次的大模型比较后归因于容量。训练数据增强和采样顺序保持匹配，不缓存错误坐标系的消息。

扩大后端优先采用保持原函数的通道复制/下游权重分摊初始化，BN参数及统计复制；并以真实输入检验复制后的输出与原始模型近似等价。未验证前不宣称零损失拼接。新模型不从随机后端起步后仅给十轮与成熟小模型比较；不同时添加蒸馏、新融合、额外监督或改预算。

拟定两臂同10轮、batch2、Adam 5e-5、7/9轮衰减、seed20260929；沿用Ldet(2KiB)+0.5Ldet(0)、消息dropout0.1和冻结BN统计，仅改变BEV容量。正式启动前落实可执行配置、实际参数计数、优化器覆盖、梯度和对齐/真实包/零消息审计，并记录独立训练输出路径、进程与超时。当前没有扩容训练进程，不与正在运行的multi248k混称。

## 验收、退出与后续定位

- 首轮以同训练预算C1相对C0的2KiB全量BEV AP70为主要容量效应；同时评估0/2/4/8KiB，保留增加消息后退化，选模只使用预定2KiB验证指标。
- 两臂导出同一1738帧的真实包、每帧字节/P95/最大值、预测及共同GT，独立CPU AP复核。参数量单列，延迟/显存另测，不能拿参数减少代替计算收益。
- 记录协作增益AP70(2KiB)-AP70(0)。若大模型仅单车和协作一起提升，说明检测容量有效，但不证明脉冲通信机制更好。
- 一次匹配十轮；若C1相对C0不足0.5 AP百分点，不连续扩展深度/宽度搜索。若明确改善，先做匹配种子复核，再考虑解冻后段SNN编码器联合适配，仍保持32通道消息接口和实际字节上限。
- 建议阶段精度目标：2KiB达到约63.2% AP70，即距CoSDH 65.175%不超过2个百分点；4KiB若作为主要工作点则争取约64%。这些是待验证的目标，不是预测，也不是用户已确认的硬门槛。必须同时比较InfoCom低率适配曲线（2.390kB/62.876%、2.736kB/63.380%），不能只对比其官方8.755kB点。
- 若大后端无明显收益，下一次主对照转向更强的SNN编码器/发送投影，保留128→32的传输瓶颈和真实字节预算。首轮不同时扩发送端，避免无法定位收益。信息已在发送前丢失时，加大后端可能无济于事；该结果同样有判别价值。

现有multi248k完成既定10轮和最终复核，不因容量新假设提前中止；容量实现准备可以并行推进。无需等待SNN计算后端调试完成才推进精度主线，也不恢复方案三。
