# 接收端膜电位请求：对齐、双向预算与冻结AP对照（2026-10-22）

## 总目标与已有方法边界

研究总目标是SNN风格协作的合格通信—AP。仅源端线性效用预测已失败，不增加其网络宽度或继续调正则。本轮尝试接收侧参与消息优先级，但不把失败解释为“缺少接收信息是唯一原因”。

已核对一手资料：[Where2comm原文§4.3](https://arxiv.org/html/2209.12836)明确使用请求图`R=1-C`和发送方置信度×接收方请求进行空间选择；[Who2com](https://arxiv.org/abs/2003.09575)已有可学习握手通信。因此，**请求反馈、空间优先级和多轮通信本身不是新颖点**。本轮仅检验一种与Count4状态相关的请求是否值得其双向成本，不宣称SNN独有优势；若有收益仍须普通置信度请求及强ANN同反馈对照。

## 一个固定的可运行候选

车端从融合前连续膜电位U计算`u=clamp(U,0,4)`、`q=floor(u+0.5)`，请求强度为`max_channel(2*relu(u-q))`。它表示有通道接近下一次向上跳变的正余量，不是已校准的不确定性，也不能识别所有漏检/未知空间。

保留全部高度层；只对XY的4×4原网格单元做最大池化，边缘块保留。强度固定量化为0..3。当前原网格3×50×126，对应请求3×13×32，共1248个2bit数，未压缩数值本体312bytes；另加完整帧/时间/几何/编码基底身份、版本与CRC，实际长度由真实序列化得到。**312bytes绝不是总通信量**。

全零请求发空包并恢复原IF顺序。非空请求用E3RQ1真实编码/解码；不把接收端连续值偷偷作为发送端输入。请求是标量空间控制信号，不传输特征通道，不把车端某通道当作路端同索引通道相加。

### 对齐

先将已解码粗请求按原XY块恢复至原生网格并裁剪边缘，再执行物理坐标变换。若`T`为road→ego，则发送端位置`x_road`查询`R_ego(T*x_road)`；调用既有pull式warp时传入`T^-1`。float64计算几何，三线性采样，不在插值前把高度折叠。对零填充域外位置作解析掩码，避免float32 grid_sample在边界留下极小正值后错误优先于真正零请求。覆盖只代表网格域，不等于可见空间/空闲区。

发送端以请求强度降序安排事件，同请求内保持原IF时刻/地址顺序；完整单位事件多重集不变。**这是请求引导的发送调度，不是改写IF神经元发放方程**；不宣称新的时间编码或增量推理加速。接收仍使用已验证源坐标累积→对齐→D/门控→Count4→ANN BEV与连续头。

## 预登记：直接检验全量AP与通信，不继续只看代理损失

固定146的SNN P+D epoch4 best，SHA `c51a33f3c1d935a8528763ddbb68ccb3298475beab842a49c5a71216c56b5a78`，全部权重/BN冻结，不训练、不接触GT生成请求。总预算预定2048和4096bytes，每点三模式：

1. **native**：无反馈，原IF全预算响应。
2. **blind**：真实发送同一个请求包、消耗预算，但发送端忽略其内容，按原IF回应剩余预算。
3. **query**：真实发送请求、按请求优先级回应剩余预算。

blind与query用于区分请求信息和预算损耗；native用于检验整个系统是否值得反馈成本。按每帧`request_bytes+response_bytes<=B`准入，完整计入两个方向的所有消息元数据，不使用免费pose/basis压缩借口。不能把回复减少称总通信减少。未建模链路帧、重传或往返时延，不能声称延迟优势。

先两帧审计原native与已有模型cls/reg/dir及bytes逐值一致、请求roundtrip、事件多重集、所有预算；通过后一次1738帧配对评估。每帧只编码一次，六模式共享本地/路端源状态，保存每个真实请求/响应、预测与索引；独立CPU复算BEV/3D及有序GT/文件SHA。至少一个预定预算下query AP70同时超过native和blind各0.1个百分点，才支持进一步研究；两个预算均须完整报告，不是总体目标已达成。

若失败，结束此固定膜电位余量请求启发式，不扫描块大小/位宽/阈值/融合增益，不自动追加训练。若成功，再准备普通置信度请求和强ANN同反馈参照，明确收益是否来自SNN状态。整个候选尚非完整新架构，创新仍须由匹配消融、AP及实测成本证明。

## 实现与检查

`e3dsnn_request.py`实现请求、严格身份/CRC、反向几何采样与事件调度；`test_e3dsnn_request.py`覆盖边缘块/高度隔离、身份/损坏拒绝、平移/亚体素/旋转方向、零请求与事件守恒。首次CPU检查发现grid_sample域外约4.8e-7数值残余，已用解析域掩码修复；不修改原检测器warp以避免改变历史基线。

`evaluate_e3dsnn_request.py`实现两帧门禁和六模式全量/CPU复核流水线。当前为启动前协议，执行状态另记；尚无本轮AP。
