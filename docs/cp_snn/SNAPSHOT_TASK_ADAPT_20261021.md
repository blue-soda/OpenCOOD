# 同实际预算的任务投影与解码适配（2026-10-21）

## 目的、边界与当前状态

共同快照工程参照已完成：2048bytes下SNN 58.16518%、ANN 59.31790%，两者约2.045kB/帧。总目标仍是可验证的SNN风格协作与合格通信—AP，不要求所有模块脉冲化，也不把压缩协议当作SNN创新。当前训练适配入口尚未完成、未启动；不得把推理审计写为训练。

可微消息选择桥已实现于`opencood/models/fuse_modules/e3dsnn_snapshot_selection.py`：复用真实codec准入，IF从原stream取可微前缀，ANN保留原量化梯度及完整行掩码、三层事件差分，尺度由实际包恢复。新增两项CPU测试连同既有三项codec测试在本地通过，覆盖P/D有限非零梯度、真实硬值、付费尺度、部分预算和零包零梯度；这不是实际检测损失梯度或训练证据。下一步接入检测器forward与正式训练工具，完成181真实增强点云审计后才启动。

下一步只检验一个假设：原先仅P、再固定P仅D的串行适配，以及旧事件封装的训练预算，未让发送内容与解码共同适应当前2048bytes快照。本轮联合更新P+D，给ANN同样的新增优化步骤，检验这个缺口能否改善实际任务表征。它不是激活类型的因果比较；两家的历史初始化、融合器、前端和消息选择不同。

## 最小实现与启动门槛

1. 复用已验证的编码、对齐、共同codec及两家接收器，新增实际字节预算的训练forward。不能把现有eval-only `FrozenSnapshot` 的numpy往返直接用于训练——那会断掉P梯度。
2. SNN继续使用已声明的固定前沿STE，以真实编码器选择的事件数生成可微前缀；ANN保留原量化STE及原三层累计顺序。排序、压缩字节及预算截断不求导，明确其偏置，不声称端到端可微的硬码率优化。ANN若直接用`counts>=k`会丢失计数梯度，需保留原训练时的阈值替代梯度。
3. 实际训练的basis摘要随P/D变化更新，绑定发送与接收双方；不同位置、车辆坐标、帧和语义通道不混加。训练使用直接计数的梯度，验证必须使用包中实际恢复的码值/尺度。不得给ANN免费尺度。
4. 本地CPU检查覆盖硬值与既有参考相同、预算边界、零包、P/D可微路径；181增强点云batch2审计同一次源编码的直接/wire预测等价、零预算等价、P/D检测梯度有限非零、其余参数和缓冲不变。丢弃该审计步。
5. 两帧epoch0输出与上一轮共同快照逐值等价（共享编码），64帧时间/显存审计通过再训练。不要为新训练重复上一轮四点全量；正式epoch0锚点仅用于选模基线。若运行成本超出已有共享GPU约束，先修实现，不启动无界慢任务。
6. 本地main提交/push，181拉取；每项训练前五次采样均值≤50%、空闲≥8192MiB，PyTorch分配上限20%。允许顺序执行，不能为并行抢占他人GPU。

## 退出与解释

只做上述两组各10轮及独立CPU BEV/3D复算，保存实际逐帧字节、最佳/最终权重冻结检查；不自动追加轮数、LR、种子或更多解码块。完整消息退化可记录为预算外行为，不能只展示最优预算。

若SNN在2048bytes相比其epoch0改善且维持超过两种单车，保留候选；相对ANN仍有差距须如实报告。是否具有通信—AP优势应看同字节两系统及后续匹配重复，而非把单次小幅越线写为证明。若联合P+D无实用收益，停止这一局部适配，回到SNN任务编码/融合的结构假设；不再次轮流微调P、D或封包。任何新的结构实验都要先提出可被消融否证的机制，并以这一强ANN参照约束论文叙事。
