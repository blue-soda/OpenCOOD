## 两阶段研究目标

第一阶段基于 E-3DSNN 证明 SNN 协同融合的精度—通信量优势。
主要精度指标为 BEV AP70，AP30/AP50、3D AP 辅助汇报。
同一 cooperative GT、数据划分和训练预算下，SNN 融合 AP70 必须高于 SNN 单车和 ANN 单车；
可以略低于 ANN 融合，但必须同时给出准确的精度差与真实编码字节，不预设“略低”的数值容忍阈值。
当前 AP70 54.26% 低于固定 ANN 单车 57.98%，尚未达到第一阶段要求。
低通信量本身不能替代精度门槛；后续等码率量化 ANN 对照用于验证表示优势。

第二阶段在第一阶段证据与 E-3DSNN 架构经验上，设计更适合跨视角对齐、融合和通信的 SNN 架构。
此阶段才集中发展结构创新；当前优先解决可复核的精度与通信权衡。

## 实施顺序和检查点审计

1. 原两组训练中 AP70 最佳均为 epoch25：SNN 54.74235%、ANN 58.89388%。
   原按 AP50 选择 epoch27，且训练仅保存 best.pth 和 last.pt。
   2026-10-15 检查完整首轮融合目录：只有 epoch27 best、epoch30 last 及过拟合权重，没有 epoch25。
   不把日志中的 AP70 冒充已恢复权重的独立结果，也不通过继续 epoch30 来冒充 epoch25。
2. CPU 逐目标诊断：固定 ego 对比 10 月 11 日 residual 归档预测。
   核对帧顺序、逐帧 GT 数组、所有文件哈希；按仓库原 score-greedy 匹配精确复现 AP50/AP70。
   输出 IoU0.7 的保留/丢失/新增 GT、最佳 IoU 分布、误检分组与置信度阈值统计。
   已保存的是 NMS 后预测，不能据此直接确定 NMS、量化或对齐的因果责任。
3. GPU 可用后先以融合 best@27 完整权重、ego 配置关闭路端，评估并 CPU 复算。
   随后从各自冻结单车 best@53/55 初始化，分别执行 cooperative GT 下 ego 30 epochs。
   使用原 batch=2、Adam 0.0002、学习率里程碑20/27、种子20260929及相同数据增强。
   ego 无融合模块可预热，因此使用30轮全模型训练；原融合为3轮融合预热+27轮联合训练。
   这是相同总轮数且给单车充分优化的对照，不宣称两者每个参数的更新次数相同。
4. 新训练以 AP70 选 best.pth，同时独立保留 best_ap50.pth、best_ap70.pth 及对应指标。
   同分保留最早轮次，恢复训练必须保持选择规则；旧状态恢复的 AP70 追踪起点另记。
   新的最佳权重均需独立评估、归档预测及 CPU 复算。
5. 依据诊断和同预算单车结果，才决定融合激活/对齐消融；不提前归因于脉冲计数。
