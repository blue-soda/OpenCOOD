# InfoCom冻结官方权重的通信—AP曲线（2026-10-26）

总目标仍是方案二SNN风格协作的AP—真实通信—计算折中优势。方案二固定2KiB/多预算两臂按预登记继续，方案三暂停；此项并行补强ANN在低通信区间的参照，不增加新的SNN结构或压缩搜索。

## 固定协议

沿用InfoCom官方完整通信模型权重及已审计sigma/std兼容映射、seed303、共同1738帧、全部有效配对、我方共同GT及原后处理。只改变官方`topk_mask`的保留比例；保留原始可学习连续mask的排序、随机打破同分规则、原4bit量化/STE表达式及真实FP32无损codec。未对已经量化的mask重新排序。正式发送端仍为256维连续latent与空间mask，80-byte身份/姿态头实际计入。

只运行预设1%、2.5%、5%三个点，原生10%已经完成（AP70=64.57136%，8754.928 B/帧）。这些是空间比例，不是每帧2/4/8KiB硬约束；以实测平均、P95、最大字节横坐标作图，不能误写成同一硬预算。三个点不依据AP增加、删除或改比例。

先在10%覆盖参数下跑原前两帧，与已归档官方wire结果比较最终预测、GT、每个真实包SHA与字节数，必须逐位相同；未通过就停止，不继续三个点。三个点各执行完整1738帧真实包往返、独立CPU逐包SHA/身份/形状校验、预测SHA及共同GT AP复算。单点GPU推理4小时上限、CPU复算1小时上限，不自动重试。

使用146 GPU4依次执行，启动前及每点连续五次检查至少8GiB可用、利用率不高于20%；不终止其他任务。脚本保存独立快照，运行中不改实现。当前服务器为共享负载，该曲线不作受控速度/能耗主表。

## 解释边界及退出

这是**冻结官方checkpoint的推理工作点曲线**，尚未给低比例做适配训练。官方训练比例最低通常为10%，因此低比例结果不能直接代表充分训练的强ANN；若方案二看似领先，必须继续提供匹配低预算训练机会，才讨论方法优势。1%/2.5%/5%全部完成后结束本项，不扫更多比例或压缩系数。随后结合实际曲线，登记必要的匹配低预算适配、统一计算测试与发送/接收消融。

实现：`evaluate_infocom.py --mask-ratio`显式覆盖及`run_infocom_ratio_curve.py`固定三点流水线。实验根目录146 `/data1/zhh/gzc/diagnostics/ann_baselines_20261025/infocom_ratio_curve_20261026`。启动和门检查结果随后追加。
