## 当前范围

按 2026-09-29 用户要求，当前先完成 E-3DSNN 单阶段适配版及同结构 ReLU ANN 的单车训练、推理与公平对照。
两条训练保持原定 60 epochs，best 按验证 AP50 选择；协同融合改造与新压缩格式留到后续。
AP 默认指 BEV AP；3D AP 单独标注。详细数据和训练协议见 [TRAINING.md](TRAINING.md)。

## 新增的推理闭环

`train_e3dsnn_single --mode eval --save-predictions --profile --eval-3d` 在正常检测输出上增加：

- 逐帧保存车端坐标系中的预测框角点、置信度和 GT，保留原数值精度和验证顺序。
- 保存 frame_id、逐文件 SHA256、预测框/GT 数量、配置与固定权重哈希。
- 同一批框计算 BEV AP 和补充 3D AP。
- CUDA 同步计时：H2D、模型前向、后处理以及合计；记录 PyTorch 峰值 allocated 显存。

`replay_e3dsnn_predictions --evaluation-dir <目录>` 不运行网络、不占 GPU，
先验证所有索引和预测文件，再重新计算两种 AP。只有指标和框数完全一致才生成 passed 报告。
因此可以将“模型这次预测了什么”和“评估器如何计算 AP”分开核验。

4 项 CPU 回归检查覆盖已知 BEV/3D AP、重复框和空帧，以及预测文件损坏、索引变化、汇总 AP 错误。
这些检查验证回放链路，不代替真实验证集运行。

## 解释边界与最终验收

1. 固定预测的 CPU AP 可以精确复算；重新执行 GPU 网络仍可能有稀疏算子和体素内点顺序造成的小幅差异。
2. 当前计时剔除前 20 帧，batch=1，合计包含 H2D、前向和 decode/NMS/GT 整理，不含读盘与预处理、AP 计算或归档。
3. batch_wait 是预取 DataLoader 的等待，不等于完整预处理耗时；共享服务器计时不作为独占硬件端到端时延或实际能耗结论。
4. 阶段轮次不同，不以本次 SNN/ANN 指标判断最终优劣。PointPillars 历史权重仍作为另列的工程参考。
5. 等两条训练各完成 60 轮后，冻结各自按 AP50 选出的 best 和元数据，重新完成全量推理归档及 CPU 复算，再汇总最终单车结果。
